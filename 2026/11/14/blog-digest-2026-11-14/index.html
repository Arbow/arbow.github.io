1. Building strong safety evaluations

来源：https://www.anthropic.com/research/building-strong-safety-evaluations
日期：2026-11-13

核心概要

文章从一个朴素的观察出发：当我们说“新模型比旧模型更安全”，其实只是说它在某套人写的评测上得分更高，所以结论的可靠程度完全取决于评测本身。作者借鉴心理学十年前“复现危机”之后的改革（预注册、更好的测量、更严格的统计），结合 Anthropic 自己做评测的经验和 system card 里的例子，给出一套构建安全评测的建议，分为设计、运行、报告三大块。

设计部分的核心是“测你真正想测的东西”。以自伤话题为例，拒答率不是合适的构念：一个对所有相关提问都拒绝的模型能拿满分，却谈不上更安全，因为用户处于危机时一味拒绝本身就是失败。Anthropic 因此改用多轮对话评测，报告“适当响应率”：整段对话中每一轮都符合领域专家写的 rubric 才算通过，任何一轮出问题整段判负。生物、网络安全这类双用途领域，理想响应也不是一刀切拒绝，而是帮助合法需求、扣住可提供实质助力的操作细节；同时要成对地放入有害提示和良性提示，既测合规也测过度拒绝。

泛化与内部效度方面，文章强调多轮模拟（由领域专家写规格，固定第一轮，另一个 Claude 模型按规格扮演用户，每个场景多次运行）、从真实使用数据出发构造场景、覆盖多语言和产品界面；并提醒数据污染、reward hacking、单轮评测饱和（API 上单轮无害率在 94%–98%）等问题。报告部分则强调预注册、样本量下限（复杂多轮至少约 100 条，单轮至少约 1000 条）、给出置信区间，以及完整记录配置：同一模型在 API 与 claude.ai 的多轮安全评测上，适当响应率差距最高达 34 个百分点。

关键洞察

  • 先写下构念，再收集数据：别默认“拒答率”就是安全；先定义“什么叫适当响应”，由领域专家写 rubric，再设计指标。
  • 用多轮模拟代替单轮提示：伤害往往在逐步升级或上下文累积中出现，单轮评测容易饱和，更适合当回归检查。
  • LLM 评分器必须先对齐人类标注：用经偶然性校正的一致性指标（如 Cohen’s kappa）比较，并以人类标注者之间的一致性为基准；评分器坏了要“大声失败”，而不是悄悄记分。
  • 评分标准要原子化、二元化：用一组是/否问题取代一个总分，并明确写出什么不算满足标准（比如免责声明不会让有害内容变无害）。
  • 报告不确定性与配置：文中例子里 98% 与 94% 的差异在统计上并不显著，不能据此说某个模型更好；API 与带系统提示的产品形态也要分开报告。

评价

优点：把评测当成一门有方法论的测量科学来写，既有原则又有具体例子（如浪漫诈骗场景的多轮模拟、98% vs 94% 不显著的案例），可操作性强；“只做三件事”的收尾建议（写下构念、用人类判断校验评分器、报告不确定性）很实用。对安全评测的运行风险（沙箱、无网络、实时监控）也有交代，比较诚实。

不足：示例几乎都来自 Anthropic 自家的评测和 system card，外部读者无法复现具体数据；很多做法（专家团队、内部模拟工具、大样本）成本高，小团队难以照搬；对如何降低评分器自身偏差，给出的更多是检查清单而非定量方案。

适用场景：做模型评测、红队或安全对齐的研究者与工程师，以及需要看懂厂商“更安全”声明的产品和采购方。做 agent 或应用级评测的开发者也能借用其中的评分器校准和报告规范。

推荐指数：⭐⭐⭐⭐ (4/5) — 方法论扎实、例子具体，对任何做 LLM 评测的人都有直接参考价值；但偏向大团队流程且数据不可复现，所以没有给到满分。
