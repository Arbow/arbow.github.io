1. The components of agent memory

来源：https://www.anthropic.com/research/components-of-agent-memory
日期：2026-11-06

核心概要

Anthropic 这篇文章用克尔凯郭尔那句「生活只能往后理解，却必须往前过」开场，点出 agent 记忆的核心矛盾：要在还不知道接下来会发生什么的时候，决定哪些经验值得留下。他们把人类记忆类比成两段分工——海马体在当下快速编码，睡眠和休息时再回放、蒸馏，整合成新皮层里的长期知识——并据此设计 agent 记忆：会话里写日志和笔记，空闲时用「做梦」（dreaming，对应 Letta / UC Berkeley 提出的 sleep-time compute）回看 transcript，纠错、补笔记、建新表征。

文中对「agent memory」的定义很干净：指 Claude 从经验（用户互动、被指派的任务）中获得、跨会话保留、之后能再读到的知识；不包括改权重、单次对话里的 in-context learning，以及 compaction（用摘要替换旧 turn）。记忆笔记被理解成一种预测：写下一条规则，等于预测「以后还会用到这个模式」。

评估分几条线。在 Continual Learning Bench（CL-Bench）1.0 的数据库问答任务里，每题开新会话，只共享持久 memory 目录；较弱模型停在未验证的猜测，更强模型会合并笔记、标记已核实事实，并最终「闭合学习环」——条目里同时有规则、证据来源和已知陷阱。宝可梦 Red 实验则测「什么值得记」：Sonnet 3.7 滥记（约 413 个文件、225 个文件夹，只拿到 1 枚徽章），把屏幕上每回合都能看到的状态也写进记忆，结果后期大量步数在整理过期档案而不是玩游戏；Fable 5 只写 9 个文件加一个 global.md，把记忆留给策略、计划和测过的规则，拿到 4 枚徽章。指导原则上，对前沿模型「只说 memory 是干什么的、不规定怎么写」往往优于「只记失败」这类硬规则；硬规则反而会削弱强模型从记忆里拿到的增益，而旧模型更需要被提示去读 memory、去验证假设。

做梦的几项能力用实验拆开：对照 transcript 纠错（Mt. Moon 里 PokéCenter 方位记错，未纠正会反复摔下单向台阶并放弃；纠正后能回到洞穴并到达华蓝市）；用 dreaming 增量构建 wiki（Stainless 约 35 万文件 / 4.2 亿 token 语料，128 轮 dreaming 后 25 题达标率从 13% 到 48%；wiki + 搜索优于只用搜索，并约省 2 万 token/题）；把笔记提升到记忆层级顶部、在会话开始时注入（类似 Claude Code auto memory 只加载 MEMORY.md 前 200 行或 25KB 作索引）；按目标塑形（Harvey LAB 并购 brief：共享合同条款表被多 agent 互踩只保留 41/57 条事实，改成「一合同一页、原文引用」后 57/57）；以及跨会话补缺（第二轮 dreaming 修断链、补索引页）。文章最后留下开放问题：当场记 vs 后台做梦的时机、纠错算力如何聚焦、表征如何避免像博尔赫斯《论科学的精确性》里那张和帝国一样大的地图。

关键洞察

  • 当场记与做梦要拆开：会话里负责捕获显著事件（salience），空闲时用 transcript 做 ground truth 纠错和压缩。只靠当场写，错误笔记会跨会话被当真信任；只靠做梦，又可能赶不上当前任务立刻要用的细节。
  • 记忆是预测，不是流水账：该记的是「屏幕上读不到、自己推出来才存在」的东西——策略、计划、已验证规则；能每回合从环境重读的状态写进 memory，只会过期并抢注意力。
  • 对强模型少下硬规则：告诉它 memory 文件夹在、用途是什么，往往比「只记失败」更能保住增益；硬规则更适合补弱模型「不读 memory / 不验证假设」的行为缺口。
  • 表征要配搜索，并控制顶部注入层：wiki 类地图在需要跨文档综合、判断或计算时帮助最大；单文档可检索的任务几乎无增益。注入上下文必须短（像 MEMORY.md 头部索引），否则既烧 token 又降低遵循度。
  • 多 agent 共建 memory 要防互踩：共享可写表容易丢事实；按资源分片、要求原文引用、再用一轮 dreaming 修断链，比事后从烂 wiki 里捞信息可靠。

评价

优点：概念框架清楚（salience → 笔记 → dreaming → 表征 / 注入），评估覆盖基准、游戏长程任务和大规模文档 wiki，数字和反例（滥记、错误地标、过大 wiki、互踩合同表）都具体，对做 agent harness 的人可直接对照自己的 memory 设计。对 Claude Code auto memory 注入上限的交叉引用也很实用。

不足：不少结论绑在 Anthropic 内部模型版本和 Managed Agents 环境上，外部无法复现「Fable 5 / Opus 5.5」等对比；dreaming 的调度策略、算力预算和失败模式只点到为止；Stainless 语料与部分 LAB 任务不可公开，读者很难按同样规模验证 wiki 收益曲线。宝可梦叙事生动，但「徽章数」与生产场景的映射仍需自己脑补。

适用场景：在做跨会话 agent、Claude Code / Managed Agents 类 harness、或准备上 auto memory / sleep-time compute 的团队；关心「记什么、何时整理、如何注入上下文」的工程师和研究人员。只做单轮 RAG、没有持久 memory 目录的产品，主要是开阔设计视野。

推荐指数：⭐⭐⭐⭐ (4/5) — agent 记忆分工和 dreaming 纠错/建表征讲得很透，实验反例有说服力，值得精读；扣一星是因为关键配方和部分评测语料不对外部开放，可落地性取决于你自己的 harness。
