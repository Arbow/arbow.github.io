1. 碎碎念

来源：https://blog.codingnow.com/2026/11/random_notes.html
日期：2026-11-20

核心概要

云风自述最近从写输入法开始恢复写代码。他给 RIME 写 Lua 插件，把拼音改成音形码，并且复用 RIME 自带的全拼字典，没有另建字典。花了近一周排查“用户造词无法写回词库”的 bug。他最终定位到根因：RIME 反查选词时只解开一层 ShadowCandidate 包装，看不到真正的 Phrase，造词信息因此丢失。他已把问题写进 Issue，并说现在应该已经修正。

第二部分写他和 yuchanns 合作给 soluna 引擎加 render target 支持。sokol 在 10 月底大改了资源管理 API，必须通过 staging buffer 上传数据。sokol 的 Mac 实现也不允许同一帧对 swapchain 多次提交。他借机把管线重构成 C 层的多 render pass，并把 uniform 设置从 Lua 挪进 C 的材质实现。他认为 soluna 目前定位为简单 2D 引擎，缺的是真实需求驱动的项目。

最后是读书和育儿。他一天读完杉山正明的《忽必烈的挑战》，对元朝的看法有所改变。他提到白银成为世界贸易货币这一点。关于孩子的数学学习，他认为不要急着给答案，让孩子试错、自己想明白，再引入成熟的公式。

关键洞察

  • LLM 适合当“小黄鸭”：LLM 能缩短陌生系统的上手时间，但他被 AI 的误导带偏了很久。他的结论是让 AI 当你的小黄鸭，不要变成你给 AI 当小黄鸭。
  • 复用基础设施要付出理解成本：复用 RIME 的字典和机制省了维护量，但需要读懂候选包装链（SimpleCandidate、ShadowCandidate、Phrase）。
  • 依赖大版本升级会逼出重构：sokol 的 API 转向现代图形 API 风格，没有简单的兼容绕法。他的做法是把数据通道收敛到一个点，这对后续做资源线程和局部更新有利。
  • 需求驱动而不是特性驱动：已有特性都是当下用得到的，用不上的先放进计划。
  • 教学重过程：先让孩子自己推导、试错，再给公式，避免变成背书。

评价

优点：这是一篇真实的第一手经验记录。技术细节具体，比如反查时没有递归解包的 bug，也有对 AI 辅助编程的克制判断。非技术部分有个人视角。

不足：这是随笔，结构松散，各主题之间没有关联。RIME 部分对不熟悉其内部机制的读者门槛较高。文中的 Issue 链接在原文页面里，这里未核实其内容。

适用场景：适合关注 AI 辅助编程利弊、RIME 输入法定制、小型游戏引擎开发的读者，也适合想看独立开发者生活状态的读者。
