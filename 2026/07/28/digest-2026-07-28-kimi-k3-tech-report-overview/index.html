Kimi K3 技术报告综述：从 K2.x 的能力叠加，到一次“三轴架构换代”

核心结论

Kimi K3 不是简单把 K2 从 1T 参数放大到 2.8T，而是在三个维度同时更换底层机制：

  1. 序列维度：从以 MLA 为主，变为 KDA 线性循环记忆 + 周期性 Gated MLA；
  2. 网络深度维度：从普通残差连接，变为可以“沿深度做注意力检索”的 AttnRes；
  3. MoE 容量维度：从 K2 的 384 专家扩展到 896 专家，并引入 Stable LatentMoE、Quantile Balancing 和 Per-Head Muon。

再加上 1M 上下文、原生图文视频输入，以及从 SFT 阶段开始的 MXFP4/MXFP8 量化感知训练，K3 实际上是一次基础架构换代，而不是 K2.7 的迭代版。(GitHub)

与 DeepSeek V4 相比，两者的方向也很不一样：

  • K3 更像“能力优先”路线：更大、更深、更多专家、原生多模态，重点是复杂 Agent、编码和知识工作；
  • DeepSeek V4 更像“效率优先”路线：通过 CSA/HCA 压缩注意力、mHC 残差流和更小的激活规模，把百万上下文的计算量和 KV Cache 明确压下来。

一句话概括：

K3 是更大、更广、更激进的架构实验；DeepSeek V4 是更克制、更可量化、更关注推理经济性的系统工程。

下表按照各自官方报告和模型卡整理。K2.5、K2.6、K2.7 虽然能力侧重点不同，但核心仍然属于 K2 的 1T/32B 激活架构族。(arXiv)

一个容易被忽略的事实是：K3 的主隐藏维度仍然是 7168。它没有主要依靠把每层做得更宽，而是把容量放在：

  • 层数：61 → 93；
  • 专家数：384 → 896；
  • 专家中间维度：2048 → 3072；
  • 激活专家：约 32B → 104B。

按公开配置粗略计算，K3 相比 K2：

  • 总参数约扩大 2.69 倍；
  • 激活参数扩大 3.19 倍；
  • 层数增加 52%；
  • 专家池扩大 2.33 倍。

所以 K3 的性能提升不能简单归功于某个“免费架构技巧”。它同时付出了非常显著的单 token 计算增长。

二、K3 真正特别的四项技术

1. KDA：把大部分序列建模从 KV Cache 改成循环状态

K3 的 93 层中，有 69 层使用 Kimi Delta Attention，只有 24 层使用完整的 Gated MLA，基本上是：

3 层 KDA + 1 层完整注意力

不断循环。

KDA 来自 Kimi Linear 工作，它可以看作对 Gated DeltaNet 的扩展。传统注意力需要保存随序列长度增长的 K、V；KDA 则维护一个固定大小的循环状态矩阵，并通过：

  • 通道级遗忘门；
  • Delta 更新；
  • 内容相关的状态写入和擦除；

把历史信息压入有限状态中。

因此，对 KDA 层来说，推理状态不会像普通 KV Cache 那样随上下文长度线性膨胀。(arXiv)

为什么仍然保留 24 层 MLA

纯循环式线性注意力有一个根本弱点：

它擅长保存“累计状态”，但不一定擅长从数十万 token 之前精确取回某个原始 token。

例如：

  • 精确复制一段随机字符串；
  • 从很多相似记录中选择其中一条；
  • 对远距离代码定义进行精确引用；
  • 处理大量相互覆盖的键值对。

这些任务更适合显式、可寻址的 KV 记忆。

因此，K3 没有采用纯 KDA，而是每隔数层插入一次完整 Gated MLA，让模型周期性地重新访问完整 token 历史。这是一种典型的混合设计：

  • KDA 负责低成本的持续记忆；
  • MLA 负责高精度的全局检索。

KDA 的速度数字应如何理解

Kimi Linear 论文中的 48B 总参数、3B 激活参数组件模型，在 1M 上下文下报告了：

  • 最多约 75% KV Cache 降低；
  • 最多约 6 倍解码加速；
  • 某些测试中 TPOT 从约 11.48ms 降至 1.84ms。

但这些数字来自一个 48B/3B、训练 1.4T token 的组件验证模型，并不是完整 2.8T K3 的端到端结果。不能直接推导成“K3 比 K2 快 6 倍”。(arXiv)

实际 K3 还同时增加了：

  • 3.2 倍激活参数；
  • 更深的网络；
  • AttnRes；
  • 更大的专家通信；
  • 周期性完整 MLA。

所以 KDA 更准确的意义是：

避免百万上下文下的 KV Cache 和解码成本失控，而不是让整个 K3 成为低成本模型。

2. AttnRes：第一次把“注意力”真正用在网络深度上

普通 Transformer 的残差结构可以简化为：

[
x_l=x_{l-1}+F_l(x_{l-1})
]

第 (l) 层只能看到前一层输出。虽然前一层理论上包含更早层的信息，但它们已经被反复压缩和叠加。

这会产生两个问题：

  • 浅层的词法、位置、视觉和局部模式不断被稀释；
  • 深层只能被动接受上一层整理好的表示，无法主动选择“我要第 8 层的局部信息，还是第 50 层的抽象信息”。

AttnRes 的做法是把不同深度的隐藏状态当成一个新的“序列”，让当前层对先前层或先前层块进行 softmax 注意力：

传统注意力沿 token 维度检索；
AttnRes 沿网络深度检索。

这相当于增加了一条“纵向寻址总线”。(arXiv)

为什么使用 Block AttnRes

如果每一层都保存并注意所有先前层输出，内存和通信会很昂贵。K3 使用的是分块版本：

  • 若干 Transformer 层组成一个 block；
  • block 内仍使用局部残差；
  • 跨 block 时，通过 AttnRes 对先前 block 表示进行选择。

这样可以把额外存储和通信控制在与 block 数量相关的范围，而不是对全部 93 层做完全连接。

AttnRes 可能解决什么问题

它最可能帮助的不是简单知识问答，而是：

  • 深层推理时保留浅层的原始约束；
  • 代码任务中重新访问早期语法和变量结构；
  • 多模态模型中保留视觉编码器的局部细节；
  • 超深网络中减轻 PreNorm 表示稀释；
  • 长 Agent 轨迹里同时维护高层计划和底层状态。

AttnRes 论文的组件实验显示，它在 scaling-law 拟合中约相当于 1.25 倍计算量的普通残差模型，同时推理延迟开销可低于约 2%。但这同样是组件模型结果，而不是完整 K3 的严格消融。(arXiv)

与普通 Dense Connection 的区别

AttnRes 不是简单把所有历史层 concat 起来，也不是固定加权：

  • 权重取决于当前 token 和当前层；
  • 不同 token 可以选择不同深度；
  • 权重通过 softmax 归一化；
  • 远距离层可以被直接访问，而不必通过几十层残差逐层传播。

这是 K3 报告中研究价值最高的部分之一。它把 Transformer 的“上下文”概念，从序列长度扩展到了网络深度。

3. Stable LatentMoE：K3 的“超稀疏”其实不等于更便宜

K3 的 MoE 配置非常激进：

  • 896 个路由专家；
  • 每个 token 选择 16 个；
  • 另有 2 个共享专家；
  • 专家隐藏维度 3072；
  • 专家路径工作在 3584 维 latent space。

与 K2 相比，它的专家池从 384 扩大到 896，但每次只使用其中约 1.79%：

[
16/896\approx1.79%
]

K2 为：

[
8/384\approx2.08%
]

DeepSeek V4-Pro 为：

[
6/384\approx1.56%
]

因此，从“选择了专家池的多少比例”看，K3 确实更加稀疏。

但看全模型激活参数占比：

模型 激活参数 / 总参数
K2 32.6B / 1.04T ≈ 3.13%
K3 104B / 2.8T ≈ 3.71%
DeepSeek V4-Pro 49B / 1.6T ≈ 3.06%

这说明：

K3 虽然从更大的专家池中选择更小比例，但它实际激活的绝对参数和总参数占比都没有下降。

“更稀疏”主要意味着：

  • 参数容量更大；
  • 专家分工可能更细；
  • 每个 token 可访问更多不同能力子空间；

而不是每 token 推理更便宜。

上述比例只是基于模型配置的粗略参数比，不等价于准确 FLOPs，因为注意力、共享专家、路由和通信成本并不完全按参数量线性变化。(GitHub)

Quantile Balancing

超大专家池最危险的问题是路由失衡：

  • 热门专家拥塞；
  • 冷门专家训练不足；
  • 不同 GPU 的 token 数量不同；
  • 动态 shape 和 all-to-all 通信效率下降。

K3 使用 Quantile Balancing，根据路由分数的分位数确定专家容量和分配，而不是依赖传统的启发式偏置更新和敏感的平衡超参数。

配合完全平衡的 Expert Parallel 训练，Moonshot 声称可以做到：

  • 每个设备形状静态；
  • 避免关键路径上的 host 同步；
  • 降低动态 token 分布导致的尾部延迟。

这类优化对 896 专家尤其重要，否则理论上的 MoE 计算节省很容易被通信和负载不均衡吃掉。(Kimi)

Per-Head Muon

K2 的代表性优化器创新是 MuonClip，重点解决 QK 范数失控和超大 MoE 预训练稳定性问题。K3 则进一步采用 Per-Head Muon，把注意力头作为相对独立的优化单元处理，减少不同头之间尺度和更新方向的相互干扰。(arXiv)

这与 K3 的设计很匹配：

  • 96 个注意力头；
  • KDA 和 MLA 两种不同性质的层；
  • Gated MLA；
  • AttnRes；
  • 多模态输入。

不同头的功能差异可能比 K2 更大，统一矩阵级优化未必是最佳选择。

4. 低精度不是事后量化，而是架构与推理系统共同设计

K3 从 SFT 阶段开始进行量化感知训练，发布配置为：

  • MXFP4 权重；
  • MXFP8 激活。

这比完成模型后再做 PTQ 更有利于保留精度，尤其是 MoE 专家、路由、KDA 状态和 AttnRes 这类对数值误差敏感的结构。需要注意的是，这不等于 K3 从预训练第一天起就在 4-bit 下训练；官方表述是从 SFT 阶段开始 QAT。(GitHub)

即使只按理想 4-bit 权重计算：

[
2.8T\times0.5\text{ Byte}\approx1.4\text{ TB}
]

这还没有包括：

  • 量化 scale 和元数据；
  • 视觉编码器；
  • 激活；
  • KDA 循环状态；
  • MLA KV Cache；
  • 通信缓冲区；
  • 并行冗余。

因此，官方建议使用 64 张以上加速卡构成 supernode，并不夸张。K3 是开放权重模型，但并不是面向普通单机部署的模型。

vLLM 为支持 K3 也不得不加入或修改：

  • KDA 循环状态缓存；
  • KDA/MLA 混合缓存；
  • 细粒度 partial prefix cache；
  • AttnRes 融合 kernel；
  • SiTU 与 MXFP4 专用路径；
  • 极大规模 Expert Parallel 支持。

这说明 K3 的复杂度已经从“模型架构创新”外溢到了推理引擎和集群拓扑层面。(vLLM)

三、K2.x 到 K3：到底哪些是版本升级，哪些是换代

K2：建立 1T 超稀疏 MoE 底座

K2 的核心贡献主要是：

  • 约 1.04T 总参数、32.6B 激活参数；
  • MLA + 超稀疏 MoE；
  • MuonClip；
  • 在约 15.5T token 训练中保持稳定，没有明显 loss spike；
  • Agent 数据合成和联合强化学习。

它本质上仍然与 DeepSeek V3 一代相似：依赖完整注意力/MLA、标准残差和经典 MoE 路由，只是在优化器稳定性与 Agent 后训练方面有明显创新。(arXiv)

K2 Thinking：主要是后训练与测试时扩展

K2 Thinking 并没有公开新的基础架构，重点是：

  • 长思考；
  • 连续 200—300 次工具调用；
  • 增加 thinking token 和工具调用次数时继续获得收益；
  • INT4 QAT；
  • 为搜索、研究和编码任务设计长轨迹 Agent 训练。

因此它更像是给 K2 装上“长推理操作系统”，不是更换发动机。(Kimi)

K2.5：多模态和 Agent Swarm

K2.5 在 K2 基础上加入 MoonViT，并使用大约 15T 图文混合 token 训练。技术亮点包括：

  • 图文联合预训练；
  • 从 4K 逐步扩展到 32K、262K；
  • Zero-Vision SFT：即使监督样本没有直接视觉输入，也训练模型主动调用视觉工具；
  • Visual Outcome RL；
  • Agent Swarm 和 PARL，让多个子 Agent 并行执行任务。

这使 K2.5 成为原生多模态 Agent，但它的语言模型主体仍然是 61 层、384 专家、Top-8 的 K2 架构族。(arXiv)

K2.6 与 K2.7

K2.6、K2.7 的公开模型配置仍然大体保持：

  • 约 1T 总参数；
  • 32B 激活参数；
  • 61 层；
  • 384 专家、Top-8；
  • MLA；
  • 256K 上下文。

变化更多来自：

  • 长时编码训练；
  • Agent 协作；
  • 工具使用；
  • 代码专门化；
  • 推理效率和交互策略。

所以从架构史角度看：

K2、K2 Thinking、K2.5、K2.6、K2.7 是同一代底座上的能力扩展；K3 才是下一代底座。

(Hugging Face)

四、K3 与 DeepSeek V4：两条百万上下文路线

1. 序列记忆：KDA 的循环压缩，对比 CSA/HCA 的显式压缩检索

DeepSeek V4 没有采用 KDA 这类循环状态，而是采用 CSA/HCA 混合结构：

CSA：Compressed Sparse Attention

大致逻辑是：

  1. 把每 4 个 token 压缩成一个表示；
  2. 为当前 query 检索相关压缩项；
  3. 只对大约 Top-1024 个条目做稀疏注意力。

它仍然保存显式、可寻址的历史，只是对历史进行了压缩和稀疏选择。

HCA：Highly Compressed Attention

HCA 使用更高的压缩率，大致将每 128 个 token 压为一个表示，然后对这些高压缩表示做全局访问。

因此两者的差别是：

K3 KDA DeepSeek V4 CSA/HCA
把历史折叠进有限循环状态 保留压缩后的显式历史条目
状态不随 token 数持续增长 缓存仍增长，但增长速度显著降低
长期累计记忆效率高 精确寻址和检索更自然
需要周期性 MLA 修复精确检索 需要训练索引器和稀疏检索
prefix cache 边界处理复杂 稀疏索引和压缩缓存复杂

DeepSeek 报告给出了很明确的百万上下文成本数据：在 1M 长度下，V4-Pro 的单 token FLOPs 约为 V3.2 的 27%，KV Cache 约为 10%；V4-Flash 分别约为 10% 和 7%。(arXiv)

K3 当前公开材料没有给出同口径的完整 2.8T 模型 FLOPs/KV 对比。因此：

可以确认 K3 的 KV 增长机制更优，但不能仅凭 KDA 组件实验断言 K3 的整机百万上下文成本低于 DeepSeek V4。

2. 深度建模：AttnRes 与 mHC 的差别

DeepSeek V4 的 mHC 可以理解为维护多个并行残差流，并通过受约束的动态矩阵在这些流之间混合。

其重要特点是混合矩阵受到双随机或 Birkhoff 类约束：

  • 每个输入流不会无限放大；
  • 每个输出流能稳定接收信息；
  • 保持残差传播的平均尺度；
  • 减少深层网络中信号坍缩或爆炸。

K3 AttnRes 则更像一次主动检索：

  • 当前层可以直接选择历史深度；
  • 不限于少数并行残差流；
  • 适合重新访问特定浅层或中间层表示。

二者解决的是相似问题，但侧重点不同：

  • mHC 强调稳定的信息传输通道；
  • AttnRes 强调内容相关的深度检索。

从理论表现力看，AttnRes 更灵活；从结构约束和稳定性可解释性看，mHC 更规整。(arXiv)

3. MoE：K3 用更多激活计算换取更大能力空间

项目 K3 DeepSeek V4-Pro
总参数 2.8T 1.6T
激活参数 104B 49B
层数 93 61
路由专家 896 384
每 token 路由 Top-16 Top-6
共享专家 2 1
激活参数占比 约 3.71% 约 3.06%

K3 总参数约是 V4-Pro 的 1.75 倍，但激活参数约是其 2.12 倍。

这意味着 K3 的策略不是仅仅扩大静态知识容量，而是允许每个 token 真正调用更多计算。其优势可能体现在：

  • 复杂代码生成；
  • 多模态推理；
  • 长工具链规划；
  • 跨领域专业任务；
  • 大规模专家分工。

代价则是：

  • 更高的每 token FLOPs；
  • 更高的专家通信；
  • 更困难的部署；
  • 更依赖高带宽 supernode。

因此，单看模型质量，K3 可能更有上限；看每美元输出 token、每卡吞吐和自部署门槛，DeepSeek V4 更有优势。

4. 多模态：这是 K3 对 DeepSeek V4 最明确的领先点

K3 从基础架构层面整合了 MoonViT-V2，面向：

  • 图片理解；
  • 视频理解；
  • GUI 操作；
  • 视觉搜索；
  • 图表与文档；
  • 视觉编码和 Agent 工作流。

DeepSeek V4 当前技术报告则明确把多模态列为后续方向，其主要贡献仍集中在文本、代码、搜索、工具使用和百万上下文。(GitHub)

所以在需要统一模型完成：

看网页截图 → 理解 UI → 写代码 → 调工具 → 检查视觉结果

这类闭环任务时，K3 的架构定位更加完整。

5. 训练与后训练：K3 更强调长轨迹状态，V4 更强调专家蒸馏

K3 默认是 always-thinking 模型，并提供 low、high、max 等推理强度。值得注意的是，它在多轮工具调用中建议保留完整 assistant 消息和 reasoning history，这有助于长 Agent 任务持续维护计划和已完成步骤。(GitHub)

DeepSeek V4 则采用：

  • specialist models；
  • 多教师统一；
  • on-policy distillation；
  • 非思考、高思考、最大思考等不同模式；
  • 搜索、编码和工具任务专门训练。

它更像先训练多个强专家，再把专家行为蒸馏进统一模型。(arXiv)

K3 的哲学更偏向“一个超大通用 Agent 内部形成专业化专家”；V4 则更明显地使用“外部专家训练—统一模型吸收”的路线。

五、评测成绩应当怎样看

选取两份官方表格中名称大致一致的项目，可以看到 K3 的公开成绩总体领先：

评测 Kimi K3 DeepSeek V4-Pro Max
GPQA Diamond 93.5 90.1
Humanity’s Last Exam 43.5 37.7
HLE with tools 56.0 48.2
BrowseComp 91.2 83.4
MCP-Atlas 84.2 73.6
GDPval-AA 1686，K3 表中为 v2 1554

(GitHub)

从结果看，K3 的优势主要集中在：

  • 搜索；
  • 工具使用；
  • MCP；
  • 知识工作；
  • 高难度推理；
  • Agent 任务。

这与它 104B 激活参数、长推理训练和多模态 Agent 定位一致。

但这些分数不能当作严格的同场考试，原因包括：

1. Harness 不同

K3 的官方表格混用了：

  • Kimi Code；
  • Claude Code；
  • Codex；
  • 不同外部 Agent harness；
  • 不同 context management 策略。

DeepSeek V4 则使用自有的最小编码和搜索 launcher，部分 Agent 任务限制为 500 步、512K 上下文。(GitHub)

2. 推理预算不同

K3 的主要成绩使用 max effort，温度 1.0；不同任务还使用不同 top-p、上下文压缩和工具配置。

因此某个分数可能同时反映：

  • 基础模型；
  • 推理 token；
  • Agent 框架；
  • 搜索工具；
  • 上下文管理；
  • 重试策略。

不能完全归因于模型权重。

3. 基准版本不同

例如：

  • K3 报告使用 TerminalBench 2.1；
  • DeepSeek V4 报告使用 TerminalBench 2.0；
  • GDPval 版本口径也可能不同；
  • Toolathlon 与 Toolathlon-Verified 不是严格相同集合。

这些项目不适合直接相减。

4. K3 缺少与 V4 同口径的 1M 精确检索成绩

DeepSeek V4 报告明确给出：

  • MRCR 1M：83.5；
  • CorpusQA 1M：62.0。

K3 主要表格没有列出完全相同的长上下文测试。K3 在 BrowseComp 中使用 300K 左右上下文压缩得到 91.2，完整 1M、不做上下文管理时为 90.4，这能证明 1M 能运行，但不等于证明 1M 内任意位置的精确取回能力优于 V4。(GitHub)

因此更谨慎的表述是：

K3 在当前公开 Agent 和知识工作评测中表现更强，但两份厂商报告不足以证明 K3 在相同计算预算、相同 harness 下全面优于 DeepSeek V4。

六、报告中最值得保留意见的地方

1. “相对 K2 提升约 2.5 倍 scaling efficiency”定义不够透明

K3 官方材料提到，相对 K2 获得约 2.5 倍 scaling efficiency。这个表述很吸引人，但不能理解成：

  • 推理速度快 2.5 倍；
  • 成本降低 2.5 倍；
  • 相同 token 数性能提升 2.5 倍；
  • 每个参数效率提高 2.5 倍。

它更可能来自内部 scaling curve：达到同一损失或能力水平时，需要的训练计算更少。但公开材料没有完整展示定义、拟合区间、对照模型和置信区间，所以它目前属于厂商 scaling 结论，而不是容易独立复现的指标。(GitHub)

而且 K3 本身激活参数比 K2 高 3.2 倍，因此即使“训练 scaling efficiency”提高，也不代表线上推理成本下降。

2. KDA 和 AttnRes 的主要消融来自组件模型

KDA 与 AttnRes 的论文实验很扎实，但其核心组件模型是：

  • 48B 总参数；
  • 3B 激活参数；
  • 训练约 1.4T token。

从 48B/3B 扩展到 2.8T/104B，中间跨越了：

  • 约 58 倍总参数；
  • 约 35 倍激活参数；
  • 更大规模专家通信；
  • 原生多模态；
  • QAT；
  • 93 层 AttnRes。

K3 证明了这些组件可以在超大规模上一起训练，但公开资料中仍缺少足够完整的全模型消融，例如：

  • K3 去掉 KDA 后怎样；
  • 去掉 AttnRes 后怎样；
  • 896 专家改回 384 后怎样；
  • 相同激活参数下与 K2 架构相比怎样；
  • 相同训练 FLOPs 下与 V4 相比怎样。

所以目前可以确认的是“系统能工作且能力很强”，但每个创新分别贡献多少，仍不够清晰。

3. K3 的推理复杂度可能成为长期负担

K3 同时包含：

  • KDA 循环状态；
  • MLA KV Cache；
  • Gated MLA；
  • AttnRes；
  • LatentMoE；
  • 896 专家；
  • SiTU-GLU；
  • MXFP4/MXFP8；
  • MoonViT-V2。

这对研究很有吸引力，但对推理引擎意味着大量专用 kernel 和缓存语义。

DeepSeek V4 自己也在报告中承认 CSA/HCA、mHC 等架构偏复杂，未来希望简化，而且某些训练稳定性原理仍未完全理解。(arXiv)

两者都表现出当前前沿开源权重模型的共同趋势：

不再只是标准 Transformer 加 MoE，而是越来越依赖模型、量化、kernel、缓存和集群拓扑共同设计。

七、我的综合判断

研究价值

K3 的研究价值很高。

真正重要的不是 2.8T 参数，而是它在一个实际发布的超大模型上同时验证了：

  • 线性循环注意力可以成为主干；
  • 完整注意力可以只周期性出现；
  • 网络深度也可以被注意力检索；
  • 近 900 个专家可以稳定训练；
  • 多模态、MoE、QAT 和 Agent 后训练可以统一在一套架构中。

尤其 AttnRes 很可能具有比 K3 本身更长的生命力。它不依赖 2.8T 模型才能使用，未来可能出现在更小的 Dense、MoE、多模态模型中。

与 K2.x 相比

K2.x 更像：

在一辆成熟车辆上不断增加长推理、多模态、代码能力和 Agent Swarm。

K3 则是：

更换发动机、变速箱、底盘和车载计算平台，同时把车做大三倍。

因此 K3 的发布意义明显高于 K2.5、K2.6 或 K2.7 的单次版本升级。

与 DeepSeek V4 相比

K3 更有优势的场景

  • 大规模多模态 Agent；
  • GUI、图片、视频与代码混合任务；
  • 高预算长推理；
  • 复杂软件工程；
  • 搜索与知识工作；
  • 拥有 64 卡以上高带宽集群；
  • 研究 KDA、AttnRes 和极大规模 MoE。

DeepSeek V4 更有优势的场景

  • 文本为主的百万上下文；
  • 重视每 token 成本；
  • 需要明确的 FLOPs/KV 数据；
  • 更看重吞吐和部署可预测性；
  • 希望使用 284B/13B 的 V4-Flash；
  • 不需要原生视觉和视频；
  • 希望以更低激活参数获得接近前沿的能力。

K2.6/K2.7 仍然有存在价值

即使 K3 更强，K2.x 并不会立即失去意义：

  • 约 1T 权重已经显著小于 K3；
  • 激活参数只有约 32B；
  • 标准 MLA 推理栈更成熟；
  • 256K 对多数代码任务已经足够；
  • K2.7 的代码专门化可能在固定预算下更实用。

对于私有化部署，K3 很可能不是“K2 的自然替代品”，而是一个更高基础设施等级的产品。

最终评价

我会把 K3 定义为：

一次以能力上限为目标的、开放权重的超大规模混合序列模型实验。

它最特别的地方不是 2.8T，而是把三种不同形式的“稀疏化”统一起来：

  • 沿序列稀疏：大部分层用 KDA，少数层做完整 MLA；
  • 沿深度选择：AttnRes 只取当前任务需要的历史层表示；
  • 沿参数稀疏：896 个专家中只激活 16 个。

DeepSeek V4 则使用另一套更工程化的三层压缩：

  • CSA/HCA 压缩序列；
  • mHC 压缩并稳定残差流；
  • Top-6 MoE 控制激活计算。

所以两者并不是同一路线上的简单胜负关系：

K3 更大、更广、更强调能力上限；DeepSeek V4 更轻、更节制、更强调百万上下文的单位成本。

截至目前，K3 在公开 Agent、搜索和知识工作评测中显示出更高的能力上限；DeepSeek V4 的长上下文成本、训练规模、消融和推理经济性披露则更加完整。K3 是更令人兴奋的研究对象，但 DeepSeek V4 可能是更容易转化为大规模商业推理服务的架构。
